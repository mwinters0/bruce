# P6.1 — License and notices: notes

What landed: `LICENSE-MIT` and `LICENSE-APACHE` at the root, `license = "MIT OR
Apache-2.0"` in `Cargo.toml`, and `THIRD-PARTY-NOTICES.txt`, generated by
`scripts/notices.py` from `cargo metadata --locked --offline`. The script's
docstring says what the file holds and how it is checked; this is what the next
slice inherits and what was refused.

## What 6.2 inherits

- **The notices file is committed, not built by the workflow.** `ThisRepo` in
  `scripts/test_notices.py` fails `mise run check` when the lockfile moves and
  the file does not, so the release workflow only copies it into the archive
  and needs no Python or cargo-about in the `debian:trixie` job.
- **The licenses are the repo's own.** The archive's `LICENSE-MIT` and
  `LICENSE-APACHE` are the root files, the Apache text copied verbatim from
  serde's `LICENSE-APACHE`; the copyright line is `Copyright (c) 2026 Michael
  Winters` (STATUS, "Decisions worth another look").
- **The file is 567 KB**, 242 crates and one entry per distinct text; crates
  differ in copyright lines, so most MIT and Apache texts do not collapse.

## Negative results

- **`cargo about` is not installed here** (mise's shim has no version set),
  and using it means pinning it in `mise.toml`, adding its config for crates
  whose license it cannot clarify, and fetching it in the workflow under the
  no-third-party-actions rule. The script is stdlib, like every `scripts/*.py`.
- **`duckdb` and `selectors` ship no license file** in their crates. They are
  listed with their expression and repository, and the line says so; the text
  of `duckdb`'s MIT is `libduckdb-sys`'s `LICENSE`, which is listed, and
  `selectors` is MPL-2.0, whose text `cssparser` ships.
- **DuckDB's bundled C++ libraries have no license text in the crate.**
  `libduckdb-sys`'s `duckdb.tar.gz` holds 26 directories under
  `third_party/` and no `LICENSE` file; the notices name the directories,
  read from the archive, and point at DuckDB's repository. The texts are not
  vendored.
- **Build-dependencies are not listed**: they run at build time and are not
  linked. A crate only a dev-dependency or another platform reaches is out too.
