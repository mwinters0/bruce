## M4's explicit-version asymmetry reviewed

- Settled by the maintainer: one rule. An explicit refspec whose version's
  baseline pages sit off their own segment is named under the segment they
  sit at, as a versionless one is; admitted as M10, which rewrites D57 (its
  `None` for that case, and its `latest_version_segment` reopen) with the
  code. Antora picks the segment by whether the version is the component's
  latest, never by how the xref names it (`computeVersionSegment`,
  `content-classifier` 3.1.15 `lib/content-catalog.js:571`), and docs.fp.o
  sets `urls.latest_version_segment: latest` (`docs-fp-o` `prod/site.yml:182`).
  So `f44@fedora::<alias>.adoc` stays `unresolved_xref` today where Antora
  resolves it; a missing page still answers `broken_url` once named (D22).
- Exposure: 23 explicit-version refspecs production leaves unresolved in
  `runs/p5.2-en-us-20261020/en-us.duckdb`, one at f44
  (`f44@fedora:release-notes:welcome/Hardware_Overview.adoc`), broken under
  either rule.
- `Held` reads a renamed segment no better (D54's reopen): filed as KD16,
  unowned. Latent for docs.fp.o's own repos: `docs/release-notes` and
  `docs/install-guide` CI playbooks (`main`, `site.yml`) set no `urls:`, so
  they build f44 under `f44/`.

## M5 landed

- `cli::interrupt` is `crawl`'s and `check-dir`'s one signal handling (D58, I24):
  SIGINT and SIGTERM are each a press, the first stops and the second abandons,
  and the exit status is 128 plus the first signal's number. A stopped or
  abandoned `check-dir` runs no gate and prints nothing to stdout. The tests are
  `tests/signals.rs`, which signal the built binary.
- KD13 is rewritten to what M6 still closes (a bare `report` reading the
  imported baseline past a later unfinished run); its marker is on
  `report::run::one`. M6 strikes it.
