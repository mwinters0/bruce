## `mise run shot` renders with Chrome in a container (M23)

The maintainer closed the "Decisions worth another look" entry on
`runs/headless-browser-trial/` with these settlements:

- **Chrome replaces Servo.** `scripts/shot.py` renders every width and makes a
  real print to PDF in Chrome's headless shell, and Servo is unpinned. Servo's
  phone render differs from Chrome's in four ways (`scripts/shot.py`'s
  docstring), and it has no paged media. The docstring's "checked in Chrome"
  rested on the gitignored trial alone.
- **Chrome runs in a container, so the host supplies no libraries.** The
  shell lacks five on this machine: `libatk-1.0`, `libatk-bridge-2.0` and
  `libatspi` from `at-spi2-core`, plus `libXcomposite` and `libXrandr`. The
  trial unpacks them from Arch packages.
- **The image is `docker.io/chromedp/headless-shell`,** pinned in `shot.py` by
  exact version tag and index digest. The pinned DejaVu fonts are mounted in.
  - **Build.** MIT-licensed, [repo](https://github.com/chromedp/docker-headless-shell).
    It's Chrome's `headless_shell`, built from Chromium source with the user
    agent made Chrome's, on `debian:trixie-slim`, with no fonts installed.
  - **Tags.** It's pushed daily under multi-arch version tags. Old tags are only
    partly kept, so the digest is the pin.
  - **On 2026-10-30:** `157.0.8103.27`, 158 MB for amd64, at index digest
    `sha256:7bee201478b2f6266aae01243740ee85c16281e32f42d3aed9fdf04f4eace7a1`.
  - **Rejected:**
    - Our own `Containerfile` around Chrome for Testing's binary: a build step,
      for Google's signature on a binary that renders our own page.
    - Debian's `chromium`, which can't be pinned exactly.
- **The runtime is a setting.** It comes from a `--runtime` flag or an
  environment variable; otherwise `podman`, then `docker`, and an error naming
  the setting when none answers.
  - Here containers run as `sudo nerdctl`, against the rootful containerd:
    there's no podman and no rootless containerd.
  - That value goes in `CLAUDE.local.md` (`../../process.md`, "CLAUDE.md
    vs. CLAUDE.local.md vs. docs"), which M23 creates and adds to `.gitignore`.
- **There's no fallback without a container.**
- **The trial is deleted once `shot` renders through the container.** Three
  facts from its `README.md` move into `shot.py`'s docstring first:
  - `FONTCONFIG_FILE` must be absolute.
  - A `--screenshot` of a URL with a fragment paints blank above the target.
  - What a fragment reveals inside `<details>`, and what print opens.
- **M23 blocks P7.** Slices 7.5 and 7.8 change the digest's HTML, whose phone
  layout and print only Chrome shows.

## Which host judges a status, and P7.3.2

Settled (maintainer, closing the "Decisions worth another look" entry on D79):

- **A status is judged by the host that answered, and `doubled_slash` by the
  host linked.** That host wrote the doubled slash, by its URL or by its
  redirect.
  - The spec's "A setting sits at the scope of what it judges" says so now.
    Read literally, it had named the linked host for both.
  - The 2026-10-28 crawl's counts are in D79's Why.
- **Each `status` map is laid over the one beneath it a code at a time.**
  Replacing would judge the same: the built-in map is the crawl's own D16
  class, `crawl/outcome.rs`. This is D79's Rejected.
- **A remapped status keeps the crawl's reason where the outcome is
  unchanged.** This is in the spec's "What a status and a severity key may
  say". 7.3 drops the reason, so a `{ 404 = "broken_url" }` erases
  `wrong_trailing_slash` and its fix. That earns **P7.3.2**, after M23 and
  7.3.1, and D79's "drops the stored reason" stands until it lands.
