## The `--externals=skip` review

**5.6.1**, P5.6 having shipped the wrong contract. D54 keeps describing the
code until 5.6.1 lands.

- **`skip` means "never ask", not "no verdict".** The spec gives it one
  purpose, "a deployer wanting no external request"
  (`../../wip/roadmap-P5-ci.md`, "What goes live"), and a copy of the
  baseline's rows asks nothing. Where the baseline holds no target, the URL is
  `unchecked`, reason `externals_skipped`. The gate's key carries the linking
  page (same spec, "A `check-dir` run is a crawl"), so a *new* link to an
  external that is broken in the baseline is introduced and fails, as under
  `baseline`. Under `unchecked` it passed, though the PR's author can fix it.
- **Under `skip`, a redirect hop onto an allowlisted host ends the chain**,
  `unchecked`, reason `externals_skipped`, as D50's `skip` does
  (`Frontier::hop_plan`). Today it is asked for its status, which breaks the
  mode's one promise.
- **`--externals` stays off in-scope URLs**: D22's `Rejected` line. P5.8's
  `check-dir.md` says that `skip` governs allowlisted hosts only, so no
  deployer reads it as an offline mode.

## The review of how a resolved xref is told

The maintainer settled 5.7's unattended call (D55) and admitted **M2**
(`../../design/out-of-band.md`). D55 and `link_verdicts` describe the code
until M2 lands.

- **Rule 1 is to read a refspec as unresolved where the link points at its own
  page or its fragment is the refspec.** A resolved link fails both: its
  component-version is not held, so it is never the linking page, and its
  fragment is the refspec's own, after its `#`, never the whole. Each test
  covers the other's hole. A `<base href>` moves the target, not the fragment.
  A refspec holding a character `url` percent-encodes in a fragment (space,
  `"`, `<`, `>`, `` ` ``) changes the fragment, not the target. There is no
  schema change.
- **Today's rule misjudges only a `<base href>` page**, in a live crawl too.
  An href `#…` and its page's row share the landing URL's canonical form, and
  `check-dir` seeds `foo/index.html` as `foo/` (`src/ci.rs`). Under a
  `<base href>` the xref is checked against the base page's anchors: usually
  `broken_anchor` with no reason, passing only where that page has none
  (`no_anchors`).
- Evidence: in `runs/p5.2-en-us-20261020/en-us.duckdb` and
  `runs/p4.10-en-us-20261019-2125/en-us.duckdb`, all 92 rows with
  `xref_refspec` point at their own page, their fragment equal to the refspec
  byte for byte.
- **Pickup:** M2 blocks nothing, since verdicts change only on a `<base href>`
  page and en-US has none. Its change amends D55's rule and drops `<base href>`
  from D55's Reopens.
