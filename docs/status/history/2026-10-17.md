## P1.4's config call reviewed: per-host keys, a root inside its scope

- The maintainer reviewed P1.4's key names and D44. The spellings and
  `include` replacing the prefix stand. The review found three holes the
  call missed, and settled each:
  - **Per-host settings move to a top-level `[host."<h>"]`**, holding
    `per_second` and `robots`; `[rate] per_second` stays the default.
    D8 limits per host, so on a root `robots` and `crawl_delay` could
    disagree between two roots on one host, and said nothing for a host a
    root's `include` reaches. `robots` is no rate, so the table leaves
    `[rate]`. `robots = false` is refused on a host no root starts on,
    since D8 obeys external hosts' robots.txt always.
  - **`crawl_delay` is dropped.** It was a per-host rate in other units,
    differing only in beating robots.txt's `Crawl-delay`. Now a
    `per_second` written for a host a root starts on beats its
    `Crawl-delay` (D18's explicit override); on any other host the slower
    wins; the default never beats it. Letting only `robots = false` pass
    `Crawl-delay` was rejected: docs.fp.o wants its disallows obeyed.
  - **`allowlist` stays apart from `[host]`**: it says whether a host's
    links are checked, `[host]` how the host is fetched, and a root's own
    host belongs in the second only. P1.4.1 adds this to D5's Rejected line.
  - **A root's `url` must be in its own scope**, refused at load.
    `Root::from_raw` accepts an `include` the start page misses today.
  - **Globs match D7's canonical URL**, not `Url::as_str()`, since the
    store and the reports show the canonical form, and that is what users
    copy. The canonicaliser is P3's (`../../design/roadmap-P3-crawler-inbox.md`).
- The first two are `P1.4.1` (`../STATUS.md`). D5, D8, D18, D40 and D44 keep
  describing the built loader until it lands.
