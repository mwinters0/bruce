## robots.txt to be read per origin; 8.15 admitted

Reviewing 8.13's call (a robots.txt hop on the asked name that gets no
response fails the name's links), the maintainer had robots.txt read per
origin: P8's spec, "robots.txt is read per origin". The facts:
`Hosts::host` keys a host's state by name alone (`src/fetch/http/host.rs`),
and `robots_txt` builds its one robots.txt from whichever link asks first
(`src/fetch/http.rs`), so a name answering on `https` but silent on `http`
or an old port had every link `error`, working `https` ones included, when
an `http` link asked first. 8.15 lands it before 8.14; D8 says what is built
until then. The maintainer affirmed that a failed robots.txt settles its
targets for the run (D8, Rejected).
