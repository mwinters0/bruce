## P10.3's calls reviewed

The maintainer reviewed 10.3's three "Decisions worth another look" entries
and two notes items (`/dwal`).

- **A fact rule reads the first element yielding a value** (D33), amending
  the spec's "the first matching element": only that lets a `pattern` choose
  among several `meta` or `h1` matches, and a rule wanting the first match
  alone has no site. Compiled `antora` reads its first `.nav-container` only;
  its facts stay compiled, so the two need not agree. An empty attribute is a
  value and empty text is not: `data-version=""` states "unversioned", and an
  empty element before the real one states nothing.
- **A run records every profile its config defines** (D78), amending "each it
  extracted by": rows written at the run's end would leave an unfinished run,
  which reports still read, without the definitions 10.5 rebuilds its
  registry from, and would differ between two runs of one config. The digest
  names a changed rule only among profiles either run's pages used; 10.5
  builds that.
- **Declared profiles become a `[[profile]]` array named by `name`**,
  amending the spec's `[profile.<name>]`: `auto` tries them in file order,
  and TOML does not order a table's keys, so 10.3's `preserve_order` relied
  on what a key-sorting formatter breaks. `[[root]]` is the precedent; the
  `profile.<name>.*` policy rows are unchanged. Slice 10.3.1, earned, lands
  it ahead of 10.4. `regex` stays a direct dependency, the spec's rules being
  regexes.
- **A declared name and region are interned, not leaked per build** (M37,
  blocking P10): 10.5 rebuilds a registry per report, which makes 10.3's
  per-build leak grow with builds, not definitions. One process-wide cache,
  as `profile::selectors` keeps, holds `'static`; widening `Profile::name`
  and `Extract::region` (10.2's notes) would turn a `Copy` name on the
  extract-to-writer path into refcounts for no feature. Landed:
  `profile::interned` holds the cache, a name and a region list each handed out
  as one `'static` per distinct text.
- **A source rule may template `repo`, `ref` and `path` over its captures**,
  amending the spec's capture-only shape: the Sphinx fixture's URL names
  neither repo, `doc/` nor `.rst` (10.1's notes), and a site with no edit
  link is `from = "url"`'s own case.
