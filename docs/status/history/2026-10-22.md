## `v0.1.0`'s Publish failed twice; M14 admitted

- **`v0.1.0` is tagged at `72f1ba0` and unpublished.** [Run
  39801257438](https://github.com/mwinters0/bruce/actions/runs/39801257438)
  built it twice (glibc and `ldd` as rc.2) and failed in Publish both times, at
  `test "$(echo "$id" | wc -w)" = 1` after `gh release create --draft`
  succeeded. Two drafts are left, ids 420877200 and 420894690, both
  `tag_name` `v0.1.0`. Attempt 2 also did not delete attempt 1's draft, so the
  runner's `drafts()` listing missed a draft 15 minutes old. The same query
  with the maintainer's token afterwards returned both.
- **Both failures fell inside GitHub incidents**: attempt 1's Publish at
  15:18:05, before "Incident with Actions Results" resolved at 15:18:46;
  attempt 2's at 15:33:56, in one opened 15:28 ("degraded performance for
  Actions, Issues and Pull Requests"). rc.1 and rc.2 passed the same step. The
  step prints nothing between create and lookup, so which way the list was
  wrong is not known.
- **The fragility is the workflow's**: it finds the release it just made by
  listing releases (6.2's notes, "A draft is not found by tag"), where the
  create call could hand it the id. M14 takes the id from the create, uploads

  draft and why. It changes no spec decision; the release is still a draft
  with its assets, then published.
- **The maintainer chose to fix it and move the tag**: after M14 lands, the
  two drafts are deleted and `v0.1.0` is re-tagged at the commit that carries
  the fix. No release has published from `v0.1.0`, so nothing immutable names

## Repoint findings for the maintainer

A full repoint at `864c1c6` read seven module groups blind. What a comment, a
`KD<k>`, the manual or a `README.md` claimed wrongly was corrected; what sits
in the register, `concepts.md` or the P9 spec is beyond an unattended round and
is listed. Each is the record's line, then the code's.

- **D3** ("An allowlisted target gets a full GET"): only a
  target an anchor link names first gets a GET, any other kind a HEAD
  (`src/crawl/frontier.rs`, `fn live`, KD4).
- **D6** ("Ad-hoc `duckdb` users see the same views as the CLI"; "`cli`
  installs them at every open"): `inverse` has no view, its statement running
  over base tables (`src/report/inverse.rs`); `Store::export_baseline` opens
  the file with plain `Store::open` (`src/store/baseline.rs`), so a baseline
  file holds no `report_*` view until `cli` opens it.
- **D9** ("`report introduced` judges every kind too, so re-reporting a CI run
  gives the rows that set its exit"): the inverse rows that set the exit under
  `--inverse=fail` are in the text note only, and `--format json` omits them
  (`src/cli/report.rs`, the `gate.rest` branch).
- **D12** ("Matching is exact, after percent-decoding"): an anchor matches the
  fragment as written or percent-decoded (`src/store/views.rs`, rule 7, pinned
  by `src/store/views/tests.rs`).
- **D13** ("A `<link>` whose `rel` is only `preconnect` or `dns-prefetch` is
  skipped"): a `<link>` with no `rel`, an empty one or no `href` is skipped too
  (`src/extract/links.rs`, `link_kind("")` is `None`).
- **D15**, **D26** ("Bodies go in an opt-in, prunable table"; "opt-in
  `bodies`"; "Tables: `runs`, `targets`, `pages`, `page_facts`, `anchors`,
  `links`, and opt-in `bodies`"): the table is created and pruned, and nothing
  in `src/` writes it (`src/store/writer.rs`, "which waits for its option");
  the list omits `meta` (`src/store/schema.rs`).
- **D16** ("`broken_url` (4xx except below, NXDOMAIN, redirect loop)"): a 3xx
  that led nowhere is `broken_url`, reason `bad_redirect`
  (`src/crawl/outcome.rs`, `answered`).
- **D22** ("A relative href is resolved against the page's production URL"): an
  href beginning `/` resolves against the build's site root, which D53 says and
  D22 omits (`src/extract/links.rs`, `resolve`).
- **D26** ("Cross-run joins then need no URL comparison"): the source page is
  matched by `url_id`, the target by URL text, `o.target IS NOT DISTINCT FROM
  b.target` (`src/report/diff.rs`, `src/report/gate.rs`).
- **D37** ("A profile ships views pivoting its keys into columns, and D19
  resolves through Antora's"; "Reopens: D19 slow over the view"): Resolve reads
  `page_facts` through `Lookup` (`src/store.rs`, `RunLookup`), and `antora_pages`
  is read by no production code, only `src/cli/tests.rs`.
- **D38** ("Extract hands the core's one lol_html pass (D11)"): under `auto` a
  second rewriter reads the generator meta first (`src/extract.rs`,
  `generator`).
- **D39** ("Only `cli` names a concrete profile, to build the registry"): true
  of production code; `src/crawl/baseline/tests.rs` names `Antora` and
  `Generic`.
- **D46** ("D28's fragment join is two key lookups from the link to the final
  page's `anchors`"): the landing target is found by `landing.url =
  t.final_url`, a string comparison (`src/store/views.rs`).
- **D47** ("each root links to the files it read"; "Each file a root read is a
  `sitemap_file` link from it"): a root links to its top-level sitemaps, and the
  files an index lists are linked from the index (`src/crawl.rs`, `discover`
  and `write_sitemap`; `src/crawl/tests.rs`,
  `a_sitemap_index_seeds_its_pages_and_each_entry_is_a_link`).
- **D49** ("Code: `crawl::Writes`, `cli::crawl::crawl`"): the close on the second
  press is `cli::interrupt::drive`, which both `crawl` and `check_dir::check`
  call (`src/cli/interrupt.rs`).
- **`concepts.md`**, "Fetchers" ("It sits above `config` (it reads the rate and
  `user_agent`)"): `fetch` reads the rate, the hosts, the roots and the robots
  token; the user agent is passed in by `cli` (`src/fetch/http.rs`,
  `Settings`, `src/cli/crawl.rs`). "The crawl" ("resolves an href beginning `/`
  against the build's site root (D53)"): the parent holds the site root and
  `extract` resolves (`src/crawl.rs`, `extract_under`).
- **P9 spec** ("The hosts of a crawl run one after the other because of the
  queue"; "holds no worker slot"): the first describes `crawl::drive` before
  M12, which now schedules per host (`src/crawl/schedule.rs`); the second
  describes a design M12 did not build, a waiter for a host's pace still
  holding a slot there, its host bounded to a share.
