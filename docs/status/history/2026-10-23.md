## Repoint findings grilled

2026-10-22's two findings for the maintainer are settled in the register.

- **D6.** It now says what is true: a one-run report is a view; `diff`,
  `introduced` and `inverse` are composed by `bruce report`, and `inverse` reads
  the base tables, because its held set is I16's layout parsed in Rust
  (`report::inverse::held`). A view for it is rejected.
- **D6, the baseline file.** `cli::export_baseline` opens the `.partial` file
  with `db::open` after the copy, so the file has the `report_*` views as well
  as the store's and the profiles' (M15, `src/cli/export_baseline.rs`); `store`
  cannot name `report` (D39). CI imports the file into a database
  `cli::db::open` opened (D52), so the gate never read them from it.
- **D9.** In JSON, the rows that set a CI run's exit are `report introduced`'s
  and `report inverse`'s. `introduced` prints its links alone, as
  `docs/manual/report.md` already said, and a JSON shape for its other sections
  is D6's rejected one.
- **D9, the inverse mode.** `report` takes no `--inverse` and no run records
  its mode, so `Request::new`'s `Fail` heads a re-reported run's inverse rows as
  failing even where it ran with `warn` (`src/report/request.rs`). D9 says so.
  A `report --inverse` flag waits for someone who re-reports a warn run, and a
  mode column in `runs` is ruled out, since D43 would refuse every published
  baseline.

## D61 reviewed: a build's reads get a lane of their own

STATUS's entry on a local build's host sharing the slots is settled: the
build's reads are to be scheduled apart from every live host.

- **The lanes are keyed by host name** (`crawl::schedule::host_of`), and a
  build's URLs carry the production host, `--prefix` being its production URL
  (D27). So a link on the site outside the build that the baseline lacks, asked
  of production as soon as it is found (`Shared::dispatch`), waits for
  `docs.fedoraproject.org`'s pace (`per_second = 1`, `docs/manual/deploy.md`)
  inside the build's own lane, holding its slots: D61's crowding, which the
  share cannot see. A URL under the prefix and not built waits in `Pending`
  until every built page is read, so it does not.
- **Only another host splits the slots**: a forge link the baseline lacks, or
  any under `--externals=live`, leaves the build's reads 32 of the 64.
- **Exempting the build's host from the share would be wrong**, exempting that
  host's live waiters with it. The key is the route, whether the build holds the
  URL (`fetch::routed`, `Routed::is_local`).
- **Unmeasured**: quick-docs' 236 pages in 8.9 s predate M12.
- **Settled: the build's reads run under a budget of their own**, outside
  `WORKERS`, the live lanes keeping D61's share of those among themselves; no
  live waiter can then hold a slot a read wants. Rejected: the build as one more
  lane of the 64, keyed by route, which fixes the crowding and cuts each of
  three lanes to 21; a lane the share does not bound inside the 64, whose free
  slots a live lane fills with waiters whenever the build has none waiting.
- **Evidence is a `crawl::schedule` test** of each case, the prefix host's live
  waiters and a forge lane; no re-timing, P9 re-measuring quick-docs.
- **The budget is 64**, a constant of its own beside `WORKERS`: a build alone
  keeps today's slots, and a fixed number keeps the test deterministic.
  Rejected: `available_parallelism`, a number differing by machine. M16 lands
  it, amending D61 (`crawl::schedule::Schedule`, one `Pool` per `Route`;
  `Shared::drive` routes by `Frontier::answered_by`). The first-listed
  tests are the evidence; no timing was taken.

## e2e's gate

`mise run e2e` has failed at its gate since `2c8f81b` (M4); `58bac0f` passes.
The planted build's `xref:ops::disks.adoc`, through the page-alias, is
introduced as `unresolved_xref` targeting its own page, where
`scripts/e2e.py`'s `PLANTED_INTRODUCED` and `PLANTED_REDIRECTED` expect D57's
derived URL. The cause is KD19: `prefix` in `src/profile/antora/resolve.rs`
passes `None` to `segment_after_component` both for `elsewhere` and for a bare
version, and the `None` arm wants a non-empty segment after the component's,
so a bare component's root page (`/ops/`) gives no prefix. A build run's
lookup is `BaselineIndex::pages_with_facts`, which sorts its URLs, so the root
page is always the first candidate and the failure is certain, not row-order
chance as KD19 reads; `resolve/tests.rs`'s fake lookup lists pages in
insertion order with the root last, and the D57 evidence test has no root
page, so neither sees it. Only a build run against a baseline reaches it
(`crawl.rs`, `xref::resolve`); a live crawl does not. Antora (3.1.15, node
24.21.0) is not the cause: the rebuilt fixture pages are byte-identical to
`fixtures/antora/pages/`. A scratch patch cutting a bare, non-`elsewhere`
version at the component's segment turns e2e green with `cargo test` passing.
Logs, both runs' stores and the patch: `runs/e2e-gate-investigation/`.

Admitted, from the maintainer's review of these facts:

- **M17**, blocking P8: `prefix` takes a bare version not served
  `elsewhere` as its own case, cut at the component's segment; the
  non-empty-segment rule stays for `elsewhere` alone. Tests: a fake lookup
  ordered as `BaselineIndex` orders its URLs, and a component with a root page
  in D57's evidence test. KD19, its code marker and its clause in `named`'s
  doc comment are struck; D57's Evidence names the new test. Rejected:
  `newest` skipping candidates that give no prefix, which hides the
  conflation and still fails a component whose only baseline page is its
  root.
- **M17 landed** as admitted: `prefix` cuts a bare version at the component's
  segment (`After::Nothing`), KD19 struck. The tests failed before the fix.

- **M18 landed**: `mise run check` runs `e2e.py` as a ninth check
  (`scripts/check.py`, `E2E_READS`) wherever the `bruce` binary can have
  changed: a package with a binary target among those run whole, so not a
  change to its tests or a comment; a path the site is built from
  (`fixtures/antora/`'s content, UI bundle and golden file); and every
  check, as without `--affected`. A workspace holding no binary leaves it
  out, `--verify` reuses its run like the others. Nothing ran e2e from M4 to
  8.4, which is how the gate stayed red unseen; a rule to remember to run it
  is what failed. `check` now takes as long as an Antora build more than
  before, whenever the binary changes.

## Rendering the digest headless

A trial of headless browsers over `fixtures/antora/digest.html` left its
renders, logs and isolated mise installs under `runs/headless-browser-trial/`
(`out/` holds the PNGs and PDFs). This machine has no fonts (`fc-list` is
empty), so any renderer needs one pinned beside it and a `fonts.conf`;
DejaVu 2.37 through mise's `github:` backend served.

- **Servo 0.7.0** (`github:servo/servo@0.7.0`, no backend options) runs
  headless with nothing beyond the font: `servoshell -z -x
  --window-size=WxH -o out.png URL`, the window alone captured, no PDF and
  no print media. At a desktop's width it matches Chrome nearly pixel for
  pixel, `::details-content` included; at 390 px it does not crush the
  tables' URL columns as Chrome does, so it misses 8.4.1's first defect.
- **Chrome's headless shell 156.0.8078.47** (Chrome for Testing, mise's
  `http:` backend with a checksum given by hand) needs `at-spi2-core`,
  `libxcomposite` and `libxrandr`, absent here and loaded for the trial off
  `runs/headless-browser-trial/archpkgs/` by `LD_LIBRARY_PATH`; it prints to
  PDF.

compares it with Chrome's headless shell once 8.6 has approved the digest.

their height a flag, and one about 794 px wide (A4) of a copy whose
`@media print` reads `@media all`, showing the print palette and opened
`<details>` but no page breaks; DejaVu is pinned beside servoshell. The
renders are for review: no check asserts on them, the spec's checks staying
the no-script test and the golden file.
Rejected for now: Playwright with Chrome's headless shell, the trial's
