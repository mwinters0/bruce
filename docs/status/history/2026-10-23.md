# 2026-10-23

## Repoint findings grilled

2026-10-22's two findings for the maintainer are settled in the register.

- **D6.** It now says what is true: a one-run report is a view; `diff`,
  `introduced` and `inverse` are composed by `bruce report`, and `inverse` reads
  the base tables, because its held set is I16's layout parsed in Rust
  (`report::inverse::held`). A view for it is rejected.
- **D6, the baseline file.** `cli::export_baseline` opens the `.partial` file
  with `db::open` after the copy, so the file has the `report_*` views as well
  as the store's and the profiles' (M15, `src/cli/export_baseline.rs`); `store`
  cannot name `report` (D39). CI imports the file into a database
  `cli::db::open` opened (D52), so the gate never read them from it.
- **D9.** In JSON, the rows that set a CI run's exit are `report introduced`'s
  and `report inverse`'s. `introduced` prints its links alone, as
  `docs/manual/report.md` already said, and a JSON shape for its other sections
  is D6's rejected one.
- **D9, the inverse mode.** `report` takes no `--inverse` and no run records
  its mode, so `Request::new`'s `Fail` heads a re-reported run's inverse rows as
  failing even where it ran with `warn` (`src/report/request.rs`). D9 says so.
  A `report --inverse` flag waits for someone who re-reports a warn run, and a
  mode column in `runs` is ruled out, since D43 would refuse every published
  baseline.
