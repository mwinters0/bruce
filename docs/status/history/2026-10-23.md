# 2026-10-23

## Repoint findings grilled

2026-10-22's two findings for the maintainer are settled in the register.

- **D6.** It now says what is true: a one-run report is a view; `diff`,
  `introduced` and `inverse` are composed by `bruce report`, and `inverse` reads
  the base tables, because its held set is I16's layout parsed in Rust
  (`report::inverse::held`). A view for it is rejected.
- **D6, the baseline file.** `cli::export_baseline` opens the `.partial` file
  with `db::open` after the copy, so the file has the `report_*` views as well
  as the store's and the profiles' (M15, `src/cli/export_baseline.rs`); `store`
  cannot name `report` (D39). CI imports the file into a database
  `cli::db::open` opened (D52), so the gate never read them from it.
- **D9.** In JSON, the rows that set a CI run's exit are `report introduced`'s
  and `report inverse`'s. `introduced` prints its links alone, as
  `docs/manual/report.md` already said, and a JSON shape for its other sections
  is D6's rejected one.
- **D9, the inverse mode.** `report` takes no `--inverse` and no run records
  its mode, so `Request::new`'s `Fail` heads a re-reported run's inverse rows as
  failing even where it ran with `warn` (`src/report/request.rs`). D9 says so.
  A `report --inverse` flag waits for someone who re-reports a warn run, and a
  mode column in `runs` is ruled out, since D43 would refuse every published
  baseline.

## D61 reviewed: a build's reads get a lane of their own

STATUS's entry on a local build's host sharing the slots is settled: the
build's reads are to be scheduled apart from every live host.

- **The lanes are keyed by host name** (`crawl::schedule::host_of`), and a
  build's URLs carry the production host, `--prefix` being its production URL
  (D27). So a link on the site outside the build that the baseline lacks, asked
  of production as soon as it is found (`Shared::dispatch`), waits for
  `docs.fedoraproject.org`'s pace (`per_second = 1`, `docs/manual/deploy.md`)
  inside the build's own lane, holding its slots: D61's crowding, which the
  share cannot see. A URL under the prefix and not built waits in `Pending`
  until every built page is read, so it does not.
- **Only another host splits the slots**: a forge link the baseline lacks, or
  any under `--externals=live`, leaves the build's reads 32 of the 64.
- **Exempting the build's host from the share would be wrong**, exempting that
  host's live waiters with it. The key is the route, whether the build holds the
  URL (`fetch::routed`, `Routed::is_local`).
- **Unmeasured**: quick-docs' 236 pages in 8.9 s predate M12.
- **Settled: the build's reads run under a budget of their own**, outside
  `WORKERS`, the live lanes keeping D61's share of those among themselves; no
  live waiter can then hold a slot a read wants. Rejected: the build as one more
  lane of the 64, keyed by route, which fixes the crowding and cuts each of
  three lanes to 21; a lane the share does not bound inside the 64, whose free
  slots a live lane fills with waiters whenever the build has none waiting.
- **Evidence is a `crawl::schedule` test** of each case, the prefix host's live
  waiters and a forge lane; no re-timing, P9 re-measuring quick-docs.
- **The budget is 64**, a constant of its own beside `WORKERS`: a build alone
  keeps today's slots, and a fixed number keeps the test deterministic.
  Rejected: `available_parallelism`, a number differing by machine. M16 lands
  it, amending D61; until then D61 describes what is built.
