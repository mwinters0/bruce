How to read this report

{% block guide_doubled_slash %} {% if judged.doubled_slash %}

{{ question("doubled-slash") }}

Sometimes page B is fine if you go there the right way, but page A links to it in a way that adds an extra slash, e.g. example.com/foo//page_B/ or example.com/foo/page_B//, or links to a URL that redirects to one like it.

If you navigate from A to B that way, page B will work, but all of its relative links (../../blah) are broken because of the extra slash in the path. They are not counted against page B, because there's nothing wrong there: the problem is in page A. So A's link is listed as broken, with the reason doubled_slash, and {% if judged.reach == "full" %}the links on B that the extra slash breaks, and those on every other page at a doubled URL that B's relative links lead on to, are counted on page A as "broken through it"{% elif judged.reach == "immediate" %}the links on B that the extra slash breaks are counted on page A as "broken through it", though not those of the pages B's relative links lead on to{% else %}the links on B that the extra slash breaks are counted nowhere, this report being set to blame page A's link alone{% endif %}.

{% endif %} {% endblock %} {% block guide_pedantic %} {% if judged.pedantic_trailing_slash %}

{{ question("pedantic") }}

Humans generally write URLs like example.com/foo but technically the correct form is example.com/foo/: notice the trailing slash. These are actually two separate web pages as far as most web servers are concerned, and if you visit the first one the web server will helpfully tell your browser, "Hey dummy, there's no page here, it's over at example.com/foo/". So your browser has to make a second request.
