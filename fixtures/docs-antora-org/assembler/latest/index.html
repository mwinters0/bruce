Antora Assembler Documentation

Antora Assembler (herein, Assembler) provides a JavaScript library and set of Antora extensions for merging content in an Antora site and publishing it in an alternative format, such as PDF. Assembler does this by producing a set of assembly files driven by the hierarchy described by the navigation data and converting those files to another format using an AsciiDoc converter provided by an exporter extension.

The exporter extension that produces the PDF format is the Antora PDF extension, which is part of the Assembler suite. Thus, if your goal is to create PDFs from the content in your site, the Antora PDF extension is the software you’re looking for. Yet, Assembler is not just limited to creating PDFs.

The core of Assembler handles merging AsciiDoc content from multiple pages into an assembly. It repeats this process for each selected component version. It then delegates to a command (e.g., asciidoctor-pdf) or function designated by an exporter extension to convert those assembly files to another format, such as PDF or EPUB. The result is referred to as an export file. Assembler then publishes the export files alongside the other files in the site.

Features

Antora Assembler provides the following capabilities and features:

  • Combines AsciiDoc content from multiple pages based on the navigation data.

  • Reconciles section heading levels to form a logical hierarchy.

  • Provides different strategies for combining the navigation hierarchy with the section hierarchy of each page.

  • Supports designating pages as special sections for create semantic documents.

  • Rewrites and scopes IDs (and any references to those IDs) to avoid conflicts across pages.

  • Rewrites references (i.e., xrefs) into internal document or public links to decouple them from the Antora referencing system (effectively converting them standard AsciiDoc notation).

  • Allows filtering by component version and/or prerelease status using a pattern-based filter.

  • Allows the navigation to be customized per export format or profile.

  • Allows content and navigation to be filtered using preprocessor conditionals.

  • Delegates to an external command to convert the AsciiDoc assemblies to the target format (or Asciidoctor.js in the case of the HTML Single Extension).

  • Supports configuring the converter command using AsciiDoc attributes or CLI option flags.

  • Can be used to export to various formats using different exporter extensions.

  • Establishes a link from each page included in an assembly to the export in which it is included.

  • Provides an API for writing new exporter extensions or calling Assembler programmatically.

Assumptions

Assembler is designed to create exports from content (i.e., pages and navigation) in an Antora site. That means your content must be organized in Antora content roots (i.e., the Antora standard file hierarchy) and you must have an Antora playbook file that configures those content roots as content sources. Assembler runs during the standard Antora site generation, (specifically the navigationBuilt event).

If you have organized your content for use with Antora, you will not be able to run an AsciiDoc converter (e.g., Asciidoctor PDF) on that content directly. That’s because AsciiDoc converters do not understand Antora’s references, structure, or scoping. Assembler bridges that gap. Assembler transforms the AsciiDoc source so it can be converted using any AsciiDoc converter, thus making it portable.

Although Assembler is designed to publish the exports along with the site, you can also use it as a tool to merely produce those exports without publishing them.

Packages

The Assembler project distributes the following packages:

Assembler Core (@antora/assembler)

Assembler is a JavaScript library for writing Antora extensions that merge content from multiple pages into a single output file. The assembly files that Assembler produces are Antora-agnostic, which means they can be converted by any AsciiDoc converter, such as Asciidoctor PDF. Assembler uses the converter metadata and convert function provided by the exporter extension to convert the assembly files to the target format.

Antora PDF Extension (@antora/pdf-extension)

The Antora PDF Extension is the official extension for producing PDFs from content in an Antora site. It generates PDFs from assembly files prepared by Assembler Core. It does so by configuring Assembler and passing it a converter (metadata and convert function). Assembler Core manages the rest of the workflow.

Antora EPUB Extension (@antora/epub-extension)

The Antora EPUB Extension is the official extension for producing EPUBs from content in an Antora site. It generates EPUBs from assembly files prepared by Assembler Core. It does so by configuring Assembler and passing it a converter (metadata and convert function). Assembler Core manages the rest of the workflow.

Antora HTML Single Extension (@antora/html-single-extension)

The Antora HTML Single Extension generates standalone HTML documents from assembly files prepared by Assembler Core. It does so by configuring Assembler and passing it a converter (metadata and convert function). Assembler Core manages the rest of the workflow.

Assembler Core is installed automatically when you install an exporter extension (e.g., Antora PDF Extension), the latter which serves as an entry point for Assembler.

Operation

The user-facing component of Assembler is the exporter extension (e.g., @antora/pdf-extension). The exporter extension configures Assembler—​effectively creating an instance of Assembler—​and provides the converter to handle conversion to the target format. From there, Assembler creates the assembly file, uses the converter provided by the exporter extension to convert the assembly files to the target format, then publishes the converted files as exports (i.e., export family) in the Antora site.

When Assembler creates the assembly files, it models the outline using the navigation data. In other words, it uses the navigation data to know which pages to merge and in which order to merge them.

An Assembler instance can either produce a single export from a component version, or an export per top-level navigation entry. When assembling content, Assembler rewrites all references in the Antora referencing system to decouple them from Antora while also avoiding ID conflicts.

Currently, each target format you want to produce requires the use of a dedicated exporter extension. The behavior of the exporter (assembly and conversion) is controlled through the use of an Assembler configuration file (e.g., antora-assembler-pdf.yml). Typically, an exporter will use an external command to handle the conversion (e.g., asciidoctor-pdf), so you can conveniently plug in and configure the AsciiDoc converter of your choice.
